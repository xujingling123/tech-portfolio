---###  一、先理解：为什么移动端需要“特殊单位”？

想象你要做一件衣服：

*   如果你用一把**固定长度的尺子**（比如 30 厘米），给所有人量体裁衣，那肯定不行。
*   小个子穿起来像长袍，高个子穿起来像短打。

手机也一样：

*   小屏幕手机：360px 宽
*   大屏幕手机：414px 宽
*   折叠屏手机：768px 宽

如果所有尺寸都用 `px`（固定像素），页面就会“变形”。

所以我们需要能**自动缩放的“智能尺子”**——这就是 `rpx`、`rem`、`vw` 等单位的作用。

* * *

### 二、常见单位详解

#### 1. `px` —— 固定的小格子 

**比喻**：  
你用一把**固定长度的尺子**，不管谁穿，都按这个标准裁衣服。

**特点**：

*   `1px` = 1 个物理像素点。
*   **不会缩放**，放大就模糊。

**适用场景**：

*   边框、细线等不需要缩放的细节。
*   `border: 1px solid #ccc`

> **不推荐用于布局和字体**，否则无法适配不同屏幕。

* * *

#### 2. `rpx` —— 微信小程序的“智能尺子” 

**比喻**：  
你有一把**智能尺子**，它能根据人的身高自动调整刻度。

*   小个子：1 尺 = 10 厘米
*   高个子：1 尺 = 20 厘米  
    但做出来的衣服比例总是一样的！

**原理**：

*   在 **iPhone 6** 上：`750rpx = 375px`（屏幕宽度）。
*   其他手机：`rpx` 会自动等比缩放。

**代码示例**：

```html
.container {
  width: 750rpx;    /* 满屏宽 */
  padding: 30rpx;   /* 内边距 */
  font-size: 32rpx; /* 字体大小 */
}
```

**优点**：

*   UniApp / 微信小程序中**开箱即用**，无需额外配置。
*   适配简单，开发效率高。

**缺点**：

*   只在小程序环境支持，H5 中无效。

> **口诀**：**“750rpx = 一整屏宽”**

* * *

#### 3. `rem` —— 可调节的“根尺子” 

**比喻**：  
你有一把尺子，它的“1厘米”是**可以调节的**。  
比如：

*   小屏幕：1rem = 10px
*   大屏幕：1rem = 14px

只要所有尺寸都用 `rem`，衣服就会按比例放大缩小。

**怎么用？**

1.  动态设置 `html` 的 `font-size`（通常用 JS 控制）。
2.  所有尺寸用 `rem`。

```javascript
// 示例：根据屏幕宽度设置根字号
function setRem() {
  const width = document.documentElement.clientWidth;
  const rem = width / 37.5; // 375px → 10px, 750px → 20px
  document.documentElement.style.fontSize = rem + 'px';
}
window.addEventListener('resize', setRem);
setRem();
```

```html
.box {
  width: 7.5rem;     /* 750px 宽度 */
  margin: 0.5rem;    /* 50px 外边距 */
  font-size: 1.6rem; /* 16px 字体 */
}
```

**优点**：

*    适合 H5 项目，适配灵活。
*   可结合 `flexible.js` 等库自动处理。

**缺点**：

*   需要 JS 配合，稍微复杂。

* * *

#### 4. `em` —— “跟爹走”的尺子 

**比喻**：  
你儿子用的尺子，刻度是**跟着你走的**。  
你用 16px 的尺子，他 `1em = 16px`；你换成 20px，他 `1em = 20px`。

**特点**：

*   `1em` = **父元素的字体大小**。
*   会**层层继承**，容易“滚雪球”变大。

```html
.parent {
  font-size: 20px;
}
.child {
  font-size: 1.5em; /* 1.5 × 20px = 30px */
}
.grandchild {
  font-size: 1.5em; /* 1.5 × 30px = 45px */ ← 容易失控！
}
```

> 适合：字体、内边距等相对尺寸。  
> 不推荐：复杂布局，容易嵌套放大。

* * *

#### 5. `vw` / `vh` —— 按屏幕比例的“百分比尺子” 

**比喻**：  
你做衣服，直接按身高体重的**百分比**来裁：

*   袖长 = 身高 × 50%
*   裤长 = 身高 × 60%

**含义**：

*   `1vw` = 屏幕宽度的 1%
*   `1vh` = 屏幕高度的 1%
*   `100vw` = 屏幕整宽

```html
.full-width {
  width: 100vw; /* 满屏宽 */
}
.header {
  height: 10vh; /* 高度占屏幕 10% */
}
```

**优点**：

*    原生支持，无需 JS。
*   适配精准，现代浏览器兼容性好。

**缺点**：

*   有些手机（如 iPhone）有刘海、底部黑条，`vh` 可能不准。
*   极端小屏或大屏需额外处理。

* * *

#### 6. `vmin` —— 更聪明的“最小比例尺” 

这是 `vw` 和 `vh` 的“升级版”，很多人不知道，但它非常实用！

**含义**：

*   `1vmin` = `vw` 和 `vh` 中**较小的那个值的 1%**。

**举个例子**：

*   手机竖屏：宽 375px，高 667px
    *   `1vw = 3.75px`
    *   `1vh = 6.67px`
    *   `1vmin = 3.75px`（取 `vw`）
*   手机横屏：宽 667px，高 375px
    *   `1vw = 6.67px`
    *   `1vh = 3.75px`
    *   `1vmin = 3.75px`（取 `vh`）

**`vmin` 总是取屏幕较短边的 1%**，确保元素不会超出屏幕。

**适用场景**：

*   响应式图标、按钮、弹窗，防止在窄屏上溢出。

```html
.icon {
  width: 10vmin;
  height: 10vmin;
  font-size: 5vmin;
}
```

> **优势**：比 `vw` 更安全，避免横屏时元素过大。

###  四、实战建议：怎么选？

#### 1. **UniApp / 微信小程序项目**

```html
/* 直接用 rpx，省心高效 */
.view {
  width: 750rpx;
  padding: 20rpx;
  font-size: 32rpx;
}
```

#### 2. **H5 项目（现代方案）**

*   方案一：`vw` + `vmin`（推荐）
    
    ```
    html {
      font-size: 1.6vw; /* 或 1vmin */
    }
    .box {
      width: 50vmin;
      font-size: 1.2vmin;
    }
    ```
    
*   方案二：`rem` + `flexible.js`（传统方案）

#### 3. **通用技巧**

*   字体：可用 `vmin` 或 `rem`，避免过小或过大。
*   宽度：优先 `100vw` 或 `rpx`。
*   弹窗/图标：用 `vmin` 防止溢出。

* * *

### 最后：没有“最好”，只有“最合适”

移动端适配的核心思想是：**让页面比例保持一致**。

*   小程序用 `rpx`，开箱即用；
*   H5 用 `vw` 或 `vmin`，原生强大；
*   `rem` 是经典方案，依然可靠。
