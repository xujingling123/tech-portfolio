---> 在 ABSD (基于架构的软件开发) 方法中，顶层被分解为 ( )。
> 
> A. 功能子系统
> 
> **B. 概念子系统**
> 
> C. 层次子系统
> 
> D. 逻辑子系统
> 
> 解析：
> 
> 在**基于架构的软件开发（ABSD）**方法中，顶层系统会被分解为**概念子系统**（也可称为 “架构子系统”）。概念子系统是从高层视角对系统架构的划分，用于构建系统的整体架构视图，支撑后续的架构设计与软件开发。因此，正确答案为 **B**。

> ABSD 体系结构需求一般来自 3 个方面，分别是系统的质量目标、系统的商业目标和 ( )。
> 
> A. 用户需求
> 
> B. 系统需求
> 
> C. 开发人员的商业目标
> 
> **D. 现有的遗留系统**
> 
> 解析：
> 
> 在 基于架构的软件开发（ABSD）方法中，体系结构需求通常来源于三个核心方面：
> 
> *   系统的质量目标（如性能、可用性、安全性等非功能性需求相关的目标）；
> *   系统的商业目标（与业务价值、市场定位等商业层面的目标紧密相关）；
> *   **现有的遗留系统**（遗留系统的架构、功能、数据等会对新系统的体系结构需求产生直接影响，如集成、迁移、复用等需求均与遗留系统相关）。
> 
> 选项 A “用户需求”、B “系统需求” 表述过于宽泛，并非 ABSD 体系结构需求特有的三类来源之一；选项 C “开发人员的商业目标” 不符合该方法中体系结构需求的来源逻辑。因此，正确答案是 **D**。

> （）不适合采用自动化测试。
> 
> A. 对人机交互无要求的系统
> 
> B. Web 应用系统
> 
> **C. 需求频繁变化的系统**
> 
> D. 实时嵌入式系统
> 
> 解析：
> 
> 自动化测试的核心优势是**重复执行效率高、长期维护成本低**，但前提是**需求相对稳定**（因为自动化测试脚本编写后，修改成本较高）。
> 
> *   **选项 A**：对人机交互无要求的系统，无需模拟复杂的界面操作，测试场景相对稳定，适合自动化测试。
> *   **选项 B**：Web 应用系统存在大量重复的测试场景（如表单提交、页面跳转等），通过自动化工具（如 Selenium）可高效实现回归测试，适合自动化测试。
> *   **选项 C**：需求频繁变化的系统，测试用例和自动化脚本需要频繁修改，维护成本会远高于手工测试的灵活性，因此**不适合**自动化测试。
> *   **选项 D**：实时嵌入式系统虽涉及硬件，但核心功能（如模块逻辑、通信协议等）可通过自动化框架结合硬件接口工具重复验证，存在适合自动化测试的场景。
> 
> 综上，答案为 **C**。

> 嵌入式系统设计中要考虑的因素有（）。
> 
> A. 可升级、可配置、易于操作、接口规范、重量、功耗、成本、开发周期
> 
> B. 实时性、容错性、安全性、可靠性、成本
> 
> C. 可移植性、可维护性、易用性、健壮性、成本、时间
> 
> **D. 功能性、性能、可靠性、安全性、成本、时间**
> 
> 解析：
> 
> 嵌入式系统设计需综合考虑**功能、非功能属性、经济成本与开发周期**等多维度因素：
> 
> *   **功能性**：明确系统需实现的核心功能，是设计的基础；
> *   **性能**：如响应速度、处理能力等，满足实时性（部分场景）、高效运行的需求；
> *   **可靠性**：保障系统在复杂环境下稳定运行（如工业控制、汽车电子等场景）；
> *   **安全性**：防止故障、攻击或误操作造成的危害（如医疗、航空领域）；
> *   **成本**：涵盖研发、生产、维护等全周期成本；
> *   **时间**：开发周期、上市时间等，影响市场竞争力。
> 
> 其他选项的不足：
> 
> *   **选项 A**：“重量” 仅对部分便携类嵌入式设备关键，不具普遍性；“可升级、可配置” 等属于局部特性，未覆盖核心维度。
> *   **选项 B**：缺少 “功能性”“性能” 等基础且核心的设计维度，覆盖不全面。
> *   **选项 C**：“可移植性、可维护性” 等偏软件质量属性，对嵌入式系统（硬件 + 软件协同）的针对性不足；“时间” 表述模糊，未明确为 “开发周期” 等核心时间维度。
> 
> 综上，正确答案为 **D**。

> 关于 NPU (神经网络处理器) 的说法，正确的是（）。
> 
> A. 计算能力强，但能耗高
> 
> **B. 计算速度快，性能好**
> 
> C. 应用广泛，但成本高
> 
> D. 设计复杂，性能一般
> 
> 解析：
> 
> NPU（神经网络处理器）是**专为神经网络计算场景定制的专用处理器**，其核心特点是通过硬件架构优化（如并行计算单元、针对矩阵运算的专用电路、存算一体设计等），大幅提升神经网络算法（如卷积、全连接、激活函数等操作）的计算效率。
> 
> *   **选项 A 错误**：NPU 通过专用架构优化，能效比（性能 / 功耗）很高，并非 “能耗高”，反而在 AI 计算场景下比通用处理器更节能。
> *   **选项 B 正确**：由于 NPU 针对神经网络计算做了深度硬件加速，因此**计算速度快、性能表现优异**，能高效支撑深度学习模型的推理或训练任务。
> *   **选项 C 错误**：“应用广泛” 是趋势，但 “成本高” 并非 NPU 的普遍核心特征（且随着技术发展，NPU 的成本在可控优化），相比之下 “计算速度快、性能好” 更能体现其本质优势。
> *   **选项 D 错误**：NPU 设计虽有针对性复杂度，但核心目标是**提升性能**，实际在神经网络场景下性能远超通用处理器，并非 “性能一般”。
> 
> 综上，正确答案为 **B**。

> 质量属性场景由刺激源、刺激、环境、制品、响应和响应度量六部分组成。性能质量属性场景主要关注系统的响应速度，可以通过效率、响应时间、( ) 和负载来客观评价性能的好坏。
> 
> A. 带宽
> 
> **B. 吞吐量**
> 
> C. 最大延迟时间
> 
> D. CPU 利用率
> 
> 解析：
> 
> 性能质量属性的核心评价指标包括**响应时间**（系统对请求的响应快慢）、**吞吐量**（单位时间内系统能处理的请求数量或数据量，体现系统的整体处理能力）、**负载**（系统能承受的最大并发量等）、效率等。
> 
> *   选项 A “带宽” 主要针对网络传输场景，并非软件系统性能评价的通用核心指标；
> *   选项 C “最大延迟时间” 是 “响应时间” 的局部体现，且表述局限，不能全面补充性能评价维度；
> *   选项 D “CPU 利用率” 是系统资源消耗指标，属于性能的间接反映，而非直接评价系统性能（如用户体验、系统处理能力）的核心指标；
> *   选项 B “吞吐量” 是衡量系统性能（处理能力）的关键指标，与响应时间、负载等结合，能全面客观评价性能好坏。
> 
> 综上，正确答案为 **B**。

> 质量属性场景是一个具体的质量属性需求，由刺激源、刺激、(B )、制品、响应和响应度量六部分组成。
> 
> A. 源头
> 
> **B. 环境**
> 
> C. 响应
> 
> D. 度量
> 
> 解析：
> 
> 质量属性场景是对系统质量属性需求的**具体、可验证**的描述，由**六部分核心要素**组成，分别是：
> 
> *   **刺激源**：产生 “刺激” 的实体（如用户、外部系统、事件等）；
> *   **刺激**：刺激源发出的动作或输入（如请求、数据、故障等）；
> *   **环境**：刺激发生时的系统状态或外部条件（如正常运行、高负载、故障场景等）；
> *   **制品**：被刺激的对象（通常为系统或系统的某一组件）；
> *   **响应**：制品对刺激的反应（如处理请求、抛出错误、调整资源等）；
> *   **响应度量**：对响应的量化衡量（如响应时间、吞吐量、错误率等）。
> 
> 结合选项分析：
> 
> *   选项 A “源头”：非质量属性场景的标准要素，属于干扰项；
> *   选项 B “环境”：是六要素之一，符合题干中缺失的部分；
> *   选项 C “响应”：虽为六要素之一，但题干后续已包含 “响应”，此处不重复；
> *   选项 D “度量”：对应 “响应度量”，并非此处缺失的要素。
> 
> 综上，正确答案为 **B**。

> 在 SAAM (软件架构分析方法) 中，主要的输入文档包括问题描述、( ) 和架构描述文档。
> 
> **A. 需求说明**
> 
> B. 测试报告
> 
> C. 设计文档
> 
> D. 开发文档
> 
> 解析：
> 
> **SAAM（软件架构分析方法）** 是用于分析软件架构对质量属性（如可修改性、可维护性、可测试性等）满足程度的方法，其核心输入文档需支撑 “从需求到架构” 的分析逻辑。
> 
> *   **选项 A（需求说明）**：需求是架构设计与分析的源头，SAAM 需要依据需求（尤其是质量属性相关需求）来评估架构是否匹配预期，因此 “需求说明” 是 SAAM 的主要输入之一。
> *   **选项 B（测试报告）**：测试报告是测试阶段的产出，而 SAAM 属于**架构分析的早期阶段**（早于测试活动），因此测试报告不是 SAAM 的输入。
> *   **选项 C（设计文档）**：设计文档是架构设计后的细化产出，SAAM 的目标是分析 “架构本身” 是否合理，而非依赖后续的设计文档。
> *   **选项 D（开发文档）**：开发文档是开发过程中的各类文档集合，并非 SAAM 分析架构时的核心、直接输入。
> 
> 综上，正确答案为 **A**。

> ABSD 模型把整个基于体系结构的软件过程划分为体系结构需求、设计、文档化、复审、实现和 ( ) 6 个子过程。
> 
> A. 测试
> 
> B. 部署
> 
> **C. 演化**
> 
> D. 运维
> 
> 解析：
> 
> **ABSD（基于架构的软件开发）** 模型将基于体系结构的软件过程划分为**6 个子过程**，分别是：体系结构需求、设计、文档化、复审、实现和**演化**。
> 
> *   软件架构并非静态的，需随着需求变化、技术发展、环境调整等持续**演化**，因此 “演化” 是 ABSD 过程中不可或缺的子过程，用于支撑架构的长期适应性。
> *   “测试”“部署”“运维” 属于软件生命周期的后续阶段活动，但并非 ABSD 模型中对 “基于体系结构的软件过程” 的核心子过程划分。
> 
> 综上，正确答案为 **C**。

> 在 DSSA（特定领域软件架构）中，领域分析阶段，获得的主要成果是（）。
> 
> A. 领域概念模型
> 
> B. 领域对象模型
> 
> **C. 领域模型**
> 
> D. 系统上下文模型
> 
> 解析：
> 
> DSSA 的**领域分析阶段**，核心目标是识别领域内的共性需求与变化性需求，建立对领域的抽象化、系统化描述。该阶段的主要成果是**领域模型**—— 它是对特定领域中核心概念、关系、行为等知识的抽象表示，涵盖了领域的本质特征与规律，为后续领域设计（基于领域模型构建架构）、领域实现（基于架构开发可复用资产）提供基础。
> 
> 对各选项的分析：
> 
> *   选项 A “领域概念模型”：仅聚焦 “概念层面”，是领域模型的一部分，并非领域分析的完整成果。
> *   选项 B “领域对象模型”：偏向 “面向对象” 的具体建模视角，领域模型的范畴更广泛（不局限于对象范式）。
> *   选项 D “系统上下文模型”：主要描述系统与外部环境的交互边界，并非领域分析（聚焦 “领域内知识抽象”）的核心成果。
> 
> 综上，正确答案为 **C**。

> 在领域设计阶段，获得的是 ( )。
> 
> A. 领域专用语言
> 
> B. 参考架构
> 
> **C. 特定领域软件架构**
> 
> D. 构件规格说明
> 
> 解析：
> 
> 特定领域软件架构（DSSA）的开发过程分为**领域分析**、**领域设计**和**领域实现**三个主要阶段：
> 
> *   **领域分析**：聚焦识别领域内的共性与变化性需求，建立领域知识模型；
> *   **领域设计**：基于领域分析的成果，设计**特定领域软件架构**—— 它是针对该领域共性需求、适配变化点的架构方案，为领域内应用系统提供架构层面的复用基础；
> *   **领域实现**：基于领域设计的架构，开发可复用的构件、工具等资产。
> 
> 对各选项的进一步分析：
> 
> *   选项 A “领域专用语言”：通常在领域实现或更后期阶段产生，用于简化特定领域的建模 / 开发，非领域设计的直接成果；
> *   选项 B “参考架构”：是更通用的架构参考（不针对特定领域的深度定制），与 DSSA “特定领域” 的核心特点不符；
> *   选项 D “构件规格说明”：属于**领域实现阶段**的成果，用于定义可复用构件的接口、行为等细节，并非领域设计阶段的产出。
> 
> 综上，正确答案为 **C**。

> 在比较批处理和管道风格时，下列说法**错误**的是（）。
> 
> A. 批处理风格每个处理步骤是一个单独的程序
> 
> B. 管道过滤风格把系统分解为几个处理步骤，这些步骤之间通过数据流连接。
> 
> **C. 管道过滤风格和批处理风格都不支持并行执行**
> 
> D. 批处理风格每一步必须在前一步结束后才能开始
> 
> 解析：
> 
> *   **选项 A**：批处理风格的典型特点是将任务分解为多个独立步骤，每个步骤常以单独程序 / 任务形式存在，因此 A 说法正确。
> *   **选项 B**：管道 - 过滤器架构的核心逻辑就是将系统拆分为多个 “过滤器”（处理步骤），步骤间通过 “管道” 传递数据流，因此 B 说法正确。
> *   **选项 C**：管道 - 过滤器风格**支持并行执行**（多个过滤器可独立处理数据流，只要数据依赖允许，能并行工作）；批处理风格虽通常顺序执行，但也并非完全不能并行。因此 “都不支持并行执行” 的表述错误。
> *   **选项 D**：批处理风格的执行逻辑是 “顺序依赖”，前一步骤完成后，下一步骤才会启动，因此 D 说法正确。
> 
> 综上，答案为 **C**。

> 在构件组装过程中，一个构件直接调用由另一个构件所提供的服务时，这种组装方式称为 (D )。
> 
> A. 顺序组装
> 
> B. 层次组装
> 
> C. 叠加组装
> 
> **D. 点对点组装**
> 
> 解析：
> 
> 本题考查构件组装方式的概念。
> 
> *   **选项 A：顺序组装**强调构件按**执行顺序**依次推进流程，核心是 “顺序执行”，而非 “直接调用服务” 的交互关系，因此不符合。
>     
> *   **选项 B：层次组装**构件按**分层结构**组织（如上层构件依赖下层构件），但 “层次” 更侧重结构的分层划分，不是 “一个构件直接调用另一构件服务” 的核心特征，因此不符合。
>     
> *   **选项 C：叠加组装**侧重于构件功能的**叠加增强**（如逐层添加功能），与 “直接调用服务” 的交互方式无关，因此不符合。
>     
> *   **选项 D：点对点组装**核心特点是**构件之间直接交互**，一个构件可直接调用另一个构件提供的服务，交互关系是 “点对点” 的直接关联，符合题干中 “直接调用服务” 的描述。
>     
> 
> 综上，正确答案为 **D**。
